# tech.news

A weekly, AI-curated digest of latest news in frontend development, design engineering, web design, and AI. Each article recaps one or more external sources and can be read in 10 minutes or less.

UI copy is French (`lang="fr"`); code, comments, and docs are English.

## Stack

- **Next.js 16** (App Router)
- **React 19** with the React Compiler
- **TypeScript 5**
- **Tailwind v4**
- **Vitest 4** + `jsdom` + `@testing-library/react`
- **ESLint 9**

## Getting started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Scripts

| Command                 | What it does                              |
| ----------------------- | ----------------------------------------- |
| `npm run dev`           | Dev server on port 3000                   |
| `npm run build`         | Production build (also runs the TS check) |
| `npm run start`         | Serve the production build                |
| `npm run lint`          | ESLint                                    |
| `npm run test`          | Vitest in watch mode                      |
| `npm run test -- --run` | Single Vitest pass (CI-style)             |

There is no typecheck script — `next build` typechecks, or run `npx tsc --noEmit` for a fast standalone check. A green test run does **not** guarantee types pass (Vitest skips type errors).

## Project layout

- `app/` — App Router routes (home, `archives`, `[date]/[slug]` articles, `mentions-legales`). Server Components by default; `'use client'` opts into client behavior.
- `components/` — shared UI grouped by surface (`article/`, `category/`, `decoration/`, `layout/`, `listing/`, `navigation/`, `shared/`, `typo/`). Named exports re-exported through a per-group `index.ts` barrel.
- `content/` — editorial content on disk (see below).
- `types/` — shared TypeScript types (`@/types` barrel).
- `utils/` — loaders, formatters, and category lookups (`@/utils` barrel).
- `__tests__/` — Vitest specs at the repo root, mirroring the source path (e.g. `app/page.tsx` → `__tests__/app/page.test.tsx`). Do not colocate tests next to source.
- `PRODUCT.md` — register, users, purpose, anti-references, design principles, visual constraints, accessibility floor. Read before scoping a feature or designing UI. Design values themselves live in `app/globals.css`, not here.
- `CLAUDE.md` — conventions, commands, and workflow guidance for Claude Code.

## Content generation

- **Articles** are written by an AI agent (`Claude Sonnet 4.6`) every Monday morning, based on the previous week's news.
- **Images** are generated by AI (`gpt-image-2`), from a single templated prompt, with article title and category color as variables. Generation is automated via the [leonardo.ai](https://app.leonardo.ai/) API.

## Content model

Content lives on disk as markdown — no CMS, no database.

- **Issues** sit in `content/issues/<YYYY-MM-DD>/`. Each folder holds an `index.md`
  (frontmatter: `date`, ordered `articles[]` slug list; body: the weekly intro) and
  one `<slug>.md` per article. The article slug is the filename.
- **Article frontmatter**: `title`, `excerpt`, `summary`, `date`,
  `reading_time`, `sources` (`[ { label, url } ]`), and `category` (`frontend`,
  `design`, `dev-ia`, `actus-ia`). The body is raw markdown and **must** start with
  `# {title}` matching the frontmatter — the rendered page H1 comes from that line.
- **Images** are resolved by convention as `/images/<YYYY-MM-DD>/<slug>.jpg`, not declared in frontmatter.
- **Static pages** live in `content/pages/<slug>.md` (raw markdown, no frontmatter).

`loadIssue(date)` in `utils/load-issue.ts` is the single entry point; it reads from
`CONTENT_ROOT` (defaults to `<cwd>/content`, repointed at a fixture tree in tests).
The frontmatter format is the contract with the AI agent that generates these files —
schema changes must be mirrored in the agent's prompt.

## Conventions

- Arrow functions for components, handlers, helpers.
- `kebab-case` file names (Next.js reserved names excepted), `PascalCase` components, `camelCase` functions/vars, `UPPER_SNAKE_CASE` for module-level constants.
- Path alias `@/*` resolves to the repo root.
- No `any` — strict typing.
